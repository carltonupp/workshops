# Scaffolding your application

Before we get started with our build out, we need to scaffold our application. Before we do that, we should have a look at the `AGENTS.md` file.

An `AGENTS.md` file is a repository-level instruction file that essentially tells your agentic tool how to go about the task you are presenting it with. In it you can set things such as technology choices, coding standards, and other things that your tooling will take into account when performing its tasks. This saves you having to specify the same standards every single time you begin a session.

While we're on the topic of sessions, something you should be aware of is the context window. Just like your brain can only keep so many things in it at one time, so can your AI tooling. The context window is basically the history of your entire session with the tool, such as preferences you have set, decisions you have made etc. As you can imagine, a large context window means slower responses, not to mention the longer something is in the window, the more likely it is to be "forgotten" by the agent. Also, the larger the context window, the more tokens your requests will use.

The lesson here is that in order to keep your AI agents working quickly and effectively, you should keep sessions short and focused, with any context required between sessions kept in markdown files that can be referenced at a later date. This is a good reminder to scope your sessions properly, just as you did with tickets before using AI.

How we understand `AGENTS.md`, and context, it's time to scaffold our repository so that it can use agentic tooling.

Before the agent takes over, the first thing you need to do is go to the `AGENTS.md` file and populate the technology choices section. Be as specific as possible such as:

- Language
- Web Framework
- ORM
- Database (I'd recommend sqlite)
- Auth library (if more than one obvious choice)

Then, in your tool of choice, open up the `agentic-coding-basics` directory and use the `init` command or equivalent.
