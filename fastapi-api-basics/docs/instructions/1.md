# Tooling up with uv

You already know how to build an API, so we'll skip the concepts and focus on what's actually new here: the modern Python toolchain.

`uv` has rapidly become the default project manager for Python. It collapses the old sprawl (pyenv, virtualenv, pip, pip-tools) into one fast binary that manages interpreters, environments, dependencies and locking. Install it:

```
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Open up the `fastapi-api-basics` directory and initialise:

```
uv init .
uv python pin 3.12
uv add "fastapi[standard]"
```

What just happened, mapped to what you know from .NET:

- `pyproject.toml` is the project manifest (your `.csproj`), declaring dependencies and `requires-python`
- `uv.lock` is the resolved lockfile - think NuGet's `packages.lock.json`. Commit both; the lockfile is what makes builds reproducible
- `.venv` was created automatically. You never activate it. `uv run <cmd>` executes any command inside the project environment, which is how every script in this workshop will be invoked
- `uv add --dev <pkg>` puts packages in a dependency group excluded from installs downstream
- `uvx <tool>` runs a one-off CLI tool ephemerally, like `dotnet tool run`

`uv init` gave you a `main.py` starter - replace its contents:

```python
from fastapi import FastAPI

app = FastAPI(title="Task Tracker")


@app.get("/")
def read_root():
    return {"message": "Task Tracker is up and running"}
```

Run `uv run fastapi dev`. That's a development server with hot reload; `/docs` serves interactive Swagger UI and `/openapi.json` the raw generated spec. Every route you declare shows up there automatically - treat `/openapi.json` as your integration contract throughout this workshop.
