# Appendix: Pythonisms for C# developers

The framework sections assumed Python would behave. This one covers the language-level sharp edges that catch people arriving from C#. Skim it now, keep it handy for whenever something surprises you.

## The type system is advisory

Annotations are metadata, not contracts - nothing checks them at runtime:

```python
def total(prices: list[int]) -> int:
    return sum(prices)

total(["a", "b"])   # runs happily, fails somewhere downstream
```

Enforcement lives in tools and boundaries: pyright or mypy give you compile-time-style checking, while Pydantic/FastAPI validate exactly what their annotations cover. Interfaces become `Protocol` (structural - satisfied implicitly, like C# should have done) or ABCs (nominal inheritance):

```python
from typing import Protocol


class Notifier(Protocol):
    def send(self, message: str) -> None: ...
```

Anything with a matching `send` *is* a `Notifier` - no declaration of intent required. Generics work in modern syntax: `def first[T](items: list[T]) -> T`.

## Names, references, and the two classic traps

Assignment binds a name to an object; it never copies. There are no value types and no `ref`/`out` - every parameter passes an object reference. Two consequences that regularly cost people an afternoon:

Mutable default arguments are evaluated **once**, at function definition:

```python
def add(task, tasks=[]):        # bug: every caller shares this list
    ...

def add(task, tasks=None):      # idiom
    tasks = tasks or []
```

Closures capture variables, not values, so loop capture binds late - opposite of C# `foreach`:

```python
handlers = [lambda: i for i in range(3)]
[h() for h in handlers]         # [2, 2, 2]
```

## Equality, hashing, truthiness

- `==` calls `__eq__` (value equality if implemented), `is` checks identity. Use `is` for `None` comparisons and nothing else.
- A plain class has reference equality until you define `__eq__`; dataclasses give you value semantics out of the box.
- Empty containers, empty strings, `0` and `None` are all falsy. `if not tasks:` is idiomatic - but be explicit when zero is meaningful data.
- `d.get(key, default)` is `TryGetValue`; `collections.defaultdict` auto-initialises missing keys.

## Encapsulation is a suggestion

`_internal` is a convention, `__name` gets mangled, nothing is enforced. Skip getter/setter ceremony entirely: expose plain attributes, and convert to `@property` later if behaviour shows up - callers never change.

## Exceptions are control flow (EAFP)

Python culture asks forgiveness rather than permission - try the operation, handle the failure - so `except KeyError` beats pre-checking membership. House rules: catch specific exceptions, never bare `except:`; preserve cause with `raise AppError(...) from exc`; no checked exceptions exist, so signatures won't tell you what can throw.

## LINQ, translated

```python
[t.title for t in tasks if t.priority == Priority.high]      # Where + Select
{t.id: t for t in tasks}                                     # ToDictionary
sorted(tasks, key=lambda t: t.due_date)[:5]                  # OrderBy + Take
any(t.overdue for t in tasks)                                # Any
next((t for t in tasks if t.id == task_id), None)            # FirstOrDefault
```

Generator expressions are lazy like `IEnumerable` but **single-shot**: exhausted after one pass, silently yielding nothing on the second. Wrap in `list()` when you need replay. `yield` makes a function an iterator; `yield` in async functions works as you'd hope.

## `using`, modules, decorators

`with` is `using` - context managers own deterministic cleanup, and resource libraries generally offer both sync and `async with` forms.

Every `.py` file is a module that executes top-to-bottom on first import; imports are runtime operations with real side effects, resolved per process. There's no compiler catching typos before your tests do. And module-level state is per-process: `uvicorn --workers 4` means four copies of anything held in memory - one more reason the database owns all state in this workshop.

Decorators are attributes that execute: `@app.get(...)` registers routes, and writing your own for cross-cutting concerns (timing, authz) is ordinary Python, not framework magic.

---

When in doubt, `uv run python` drops you into a REPL where `type(x)` and `dir(x)` answer most questions. The feedback loop is the language's best feature - use it.
