# Data layer

The Python ORM landscape: SQLAlchemy is the long-standing standard, and SQLModel - written by FastAPI's author - layers Pydantic on top of it so a single class is both a validated DTO and a table model. For an API-first service at this scale it's the pragmatic choice, and since it's SQLAlchemy underneath (2.0-style, typed), nothing here is throwaway if you later graduate to full SQLAlchemy plus Alembic.

```
uv add sqlmodel
```

The three moving parts:

```python
from sqlmodel import Field, Session, SQLModel, create_engine, select


class TaskBase(SQLModel):
    title: str
    description: str | None = None
    priority: Priority = Priority.medium


class Task(TaskBase, table=True):
    id: int | None = Field(default=None, primary_key=True)


engine = create_engine("sqlite:///tasks.db")


def get_session():
    with Session(engine) as session:
        yield session
```

Note the model family pattern: `TaskBase` holds shared fields, `Task` adds the database identity. Your request models (`TaskCreate`, `TaskUpdate`) also derive from `TaskBase`, so the wire format and schema can't drift apart.

Endpoints receive sessions through the DI container:

```python
@app.get("/tasks")
def list_tasks(status: Status | None = None, session: Session = Depends(get_session)):
    query = select(Task)
    if status:
        query = query.where(Task.status == status)
    return session.exec(query).all()
```

Wire `SQLModel.metadata.create_all(engine)` into your lifespan handler for now. It's schema-sync, not migrations - fine for development, and we'll note the migration path in the final section.
